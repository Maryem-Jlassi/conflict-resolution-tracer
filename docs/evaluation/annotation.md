# Annotation

This page describes the annotation workflow, guide structure, independent source selection, adjudication rules, pilot status, and templates used for CRT evaluation.

## Annotation Guide Structure

The annotation process is defined in `research_evaluation/dataset.py` and documented in the dataset cards under `docs/research_evaluation/`.

### Label Set

Each conflict case receives one of five labels:

| Label | Meaning |
|-------|---------|
| `existing` | The existing claim is correct; the incoming claim is wrong. |
| `incoming` | The incoming claim is correct; the existing claim is wrong. |
| `both_compatible` | Both claims are compatible (e.g., they apply to different valid contexts or time windows). |
| `both_wrong` | Both claims are wrong. |
| `unresolved` | There is insufficient evidence to decide; abstention is the correct outcome. |

### Annotation Template

Templates are generated by `research_evaluation/dataset.py::export_annotation_template()`:

```python
def export_annotation_template(cases: list[ConflictCase]) -> list[dict[str, Any]]:
    return [{**row, "annotation": {"label": None, "rationale": ""}}
            for row in blind_package(cases)]
```

The template is a blinded JSON payload. Each row contains only the fields permitted by `blind_package()` (see [Methodology](./methodology.md)). The annotator fills in:

- `label`: One of the five valid labels.
- `rationale`: Free-text explanation of the decision.

## Independent Human Source Selection

- Annotations must come from **independent human sources** with no access to CRT outputs, baseline outputs, Ψ scores, hypotheses, or adjudicated outcomes.
- The `blind_package()` function strips all CRT-generated fields before export:
  - `lcm_output`, `psi`, `psi_scores`, `baseline_outputs`, `hypothesis`
  - `annotator_records`, `adjudicated_outcome`
- Annotators should not be involved in system development or baseline tuning.

## Adjudication Rules

Adjudication is handled by `research_evaluation/dataset.py::adjudicate()`:

1. **Agreement phase**: Two independent annotators label each case.
2. **Agreement check**: If both annotators produce the same label, the case moves to `adjudication_status = "agreement"`.
3. **Disagreement phase**: If annotators disagree, an adjudicator reviews the case.
   - The adjudicator appends an `AnnotatorRecord` with their own label and rationale.
   - `adjudicated_outcome` is set to the adjudicator's label.
   - `adjudication_status` is set to `"adjudicated"`.
4. **Escalation**: Cases that cannot be resolved by the adjudicator (e.g., genuine ambiguity, missing evidence) are marked `"escalated"`.

### Inter-Annotator Agreement

Agreement is measured with:

- **Cohen's kappa** (`cohens_kappa`) for two annotators.
- **Krippendorff's alpha nominal** (`krippendorff_alpha_nominal`) for multiple annotators.

Low agreement triggers adjudication or dataset revision.

## Pilot Annotation Status

> **Pilot annotation is pending.**

Per the preregistered protocol (`docs/research_evaluation/protocol.md`):

- Pilot observations are excluded from threshold selection and primary analysis.
- The 16+3 set is a frozen pilot, not the final held-out dataset.
- Corrected Benchmark D scenarios are diagnostic, not empirical.
- Pilot data may be used to refine annotation guidelines and estimate annotation time, but not to tune system parameters.

## Annotation Templates

Templates are produced by `export_annotation_template()` and consumed by `import_annotations()`:

```python
# Export
template = export_annotation_template(cases)

# ... annotators fill in labels and rationales ...

# Import
annotated_cases = import_annotations(
    cases,
    package=annotated_payload,
    annotator_id="annotator_01",
    annotated_at=datetime.utcnow(),
)
```

The import function:

- Matches each row by `case_id`.
- Appends an `AnnotatorRecord` to the case.
- Sets `adjudication_status = "in_progress"`.
- Skips rows where `label` is `None` (incomplete annotations).

## Validation

After import, cases are validated with `research_evaluation/dataset.py::validate_cases()`:

- Duplicate `case_id` values are rejected.
- `adjudicated_outcome` is required when `adjudication_status == "adjudicated"` (enforced by Pydantic `model_validator`).
